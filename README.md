# itplow

`itplow` — MVP веб-платформы для проектов гражданской науки. Проект объединяет учёных и волонтёров: учёный публикует проект и задания, волонтёр присоединяется, отправляет наблюдения, а учёный проверяет и модерирует результаты.

Проект выполнен в рамках кейса «Создание веб-платформы для проектов гражданской науки» для ознакомительной практики по направлению 02.03.02 «Фундаментальная информатика и информационные технологии».

## Цель проекта

Сделать упрощённый full-stack сервис, который покрывает базовый цикл citizen science:

- регистрация и авторизация пользователей
- разделение ролей на учёного и волонтёра
- создание проектов и заданий
- участие в проектах
- отправка наблюдений и отчётов
- проверка и смена статуса отчётов
- поиск и просмотр проектов

## Что реализовано

### Для волонтёра

- регистрация и вход в систему
- просмотр списка проектов
- поиск проектов по названию, описанию и категориям
- просмотр страницы проекта и списка заданий
- присоединение к проекту
- отправка наблюдений по заданиям
- просмотр своего профиля и обновление данных

### Для учёного

- регистрация с ролью `scientist`
- создание и редактирование проектов
- создание и редактирование миссий внутри проекта
- просмотр отчётов по своим проектам
- модерация наблюдений: `pending` / `accepted` / `rejected`

### На уровне платформы

- gateway как единая точка входа в API
- отдельные микросервисы по доменам
- хранение сессий в Redis
- файловое хранилище MinIO для материалов наблюдений
- автоматические миграции БД при старте сервисов

## Архитектура

Проект разделён на два крупных блока:

- `frontend/` — пользовательский интерфейс на Next.js
- `backend/` — микросервисный backend на Rust

### Backend-сервисы

- `gateway` (`:8080`) — маршрутизация запросов, CORS, проверка токенов и сессий
- `user-service` (`:8081`) — пользователи, профиль, логин, участие в проектах
- `project-service` (`:8082`) — проекты и миссии
- `observation-service` (`:8083`) — наблюдения, комментарии и файлы

### Инфраструктура

- `users-db` — PostgreSQL для `user-service`
- `projects-db` — PostgreSQL для `project-service`
- `observations-db` — PostgreSQL для `observation-service`
- `redis` — сессии и обмен событиями
- `minio` — хранение файлов наблюдений

## Пользовательские роли

- `volunteer` — участвует в проектах и отправляет наблюдения
- `scientist` — создаёт проекты и миссии, проверяет отчёты
- `admin` — системная роль backend, не создаётся через публичную регистрацию

## Быстрый запуск

### Предварительные требования

- Docker и Docker Compose
- Node.js 20+ и npm

### 1. Клонирование репозитория

```bash
git clone https://github.com/kontar1423/itplow.git
cd itplow
```

### 2. Запуск backend

```bash
cd backend
docker compose up --build
```

После старта будут доступны:

- `http://localhost:8080` — API gateway
- `http://localhost:8081` — user-service
- `http://localhost:8082` — project-service
- `http://localhost:8083` — observation-service
- `http://localhost:9001` — MinIO Console

### 3. Запуск frontend

В новом терминале:

```bash
cd frontend
npm install
npm run dev
```

Frontend будет доступен по адресу:

- `http://localhost:3000`

Frontend ожидает backend gateway на `http://localhost:8080/api`.

## Основные пользовательские сценарии

### Сценарий волонтёра

1. Зарегистрироваться и войти в систему.
2. Найти проект через каталог.
3. Присоединиться к проекту.
4. Открыть задание.
5. Отправить наблюдение или отчёт.

### Сценарий учёного

1. Зарегистрироваться с ролью `scientist`.
2. Создать проект.
3. Добавить миссии внутри проекта.
4. Просматривать поступившие наблюдения.
5. Подтверждать или отклонять отчёты.

- проект сфокусирован на базовом сценарии кейса без сложной аналитики и расширенной модерации

- для `master` в MAI-репозитории прямой push защищён серверной политикой

Репозиторий покрывает ключевые требования учебного кейса:

- full-stack приложение с двумя ролями пользователей

- локальный запуск и воспроизводимое окружение через Docker Compose
- техническая документация для демонстрации и защиты проекта
